# MyDeployMate 可行性分析与实施计划

> 版本：草稿 v0.4 · 2026-10-21（v0.4：新增第 8 节阶段 0 验证结论；v0.2：前端定为 Vue，新增第 7 节原 Demo 对照；v0.3：第 6 节全部决策已确认，任务列表同步更新）
> 依据：《软件需求规格说明书》v0.1（下称 SRS）、《交互设计说明书》v0.1（下称 IXD）、原型 `demo/server_manager_demo.py`
> 技术栈：Rust + Tauri 2 + TypeScript/HTML，Windows 客户端，Linux SSH 目标
> 说明：本文只做分析与规划，不包含任何已实现代码。所有 crate 能力判断标注了“已知可行”或“需验证”，需验证项放在阶段 0 的技术验证里先跑通。

## 1. 总体结论

两份文档质量很高：边界清楚（只有本地命令、SFTP、SSH 三种执行能力）、状态定义完整、验收用例可执行。**整体在 Rust + Tauri 上可行，没有需要推翻的需求。**

真正的工作量和风险集中在执行层，而不是界面：

1. SSH/SFTP 库的选择和 Windows 下的认证兼容（Agent、加密私钥）。
2. 取消与“结果未知”的语义（本地进程树、远程进程）。
3. sudo 运行时密码的安全输入通道。
4. SFTP 单文件安全替换（原子覆盖）。
5. 中文 Windows 下本地命令输出的编码（GBK/UTF-8 混杂）。这一点文档没有提到，但对你的环境很可能是第一个踩到的坑。

界面部分（10 个页面、5 个弹窗）工作量大但技术上没有难点，主要是脏表单管理、长日志虚拟滚动和键盘可达性。

## 2. 推荐技术选型

| 层 | 推荐 | 理由 / 备注 |
|---|---|---|
| 桌面框架 | Tauri 2.x | WebView2 在 Win11 预装；冷启动 < 3 秒容易达成 |
| SSH / SFTP | `russh` + `russh-sftp`（纯 Rust、tokio 异步） | 不依赖 OpenSSL，Windows 构建省事；主机密钥回调可完全自控（满足 SRV-03）。备选 `ssh2`（libssh2 绑定）功能成熟但 Windows 需处理 OpenSSL/静态链接，且同步 API 需包线程 |
| 异步运行时 | tokio | Tauri 2 自带 |
| 本地进程 | `tokio::process` + Windows Job Object（`process-wrap` 或 `windows` crate） | 用 Job Object 才能可靠“终止进程树”（RUN-05） |
| 配置存储 | `workspace.json`（带 `schemaVersion`）+ 原子写（临时文件 → rename）+ `.bak` | 与导入导出格式同构，CFG-01 实现最省 |
| 历史/运行记录 | SQLite（`rusqlite`）存运行与任务状态，日志另存 `logs/<runId>.jsonl` | RUN-07 要求每次状态变化落盘，SQLite 事务天然合适；日志按文件便于 50 MiB 截断 |
| 单实例 / 工作区锁 | `tauri-plugin-single-instance` + 工作区文件锁（`fs4`） | DATA-04 |
| 凭据内存 | `secrecy` + `zeroize` | SEC-03“尽力清理”，文档已接受无法保证物理擦除 |
| ID | UUID v7 | DATA-02，不可变、可排序 |
| 前端 | **Vue 3（已定）** + TypeScript + Vite + Pinia + Vue Router | 组合式 API + `<script setup>`；状态按领域拆 store（workspace、run、ui） |
| 图标 | `lucide-vue-next` | Demo 已用 Lucide（ISC 许可），风格可直接延续 |
| UI 组件 | 自建轻量组件，样式沿用 Demo 的 CSS 变量 | 不引入重型组件库（Element Plus 等），避免与 IXD 的焦点/弹窗规则冲突；复杂交互（弹窗焦点陷阱、菜单）可用 Reka UI（原 Radix Vue）这类无样式组件 |
| 前后端类型 | `tauri-specta` 或 `ts-rs` 从 Rust 生成 TS 类型 | 校验以 Rust `core` 为唯一来源，前端不重复写业务校验 |
| 日志前端 | `@tanstack/vue-virtual` 虚拟列表 + 后端批量推送（Tauri `Channel`，约 50–100ms 合批） | NFR-01：10000 行、1 秒内可见 |
| 测试目标机 | Docker 内的 OpenSSH 服务器（可配多用户、sudoers 组合） | 自动化覆盖 AC-03/04/13/20/21/22 |

工程结构建议用 Cargo workspace，把业务逻辑和 Tauri 隔离：

```
crates/
  core/      领域模型、校验、变量解析、任务展开、状态机（纯逻辑，无 IO，单测为主）
  store/     工作区读写、备份、导入导出、SQLite 历史
  exec/      本地执行、SSH、SFTP、sudo、主机信任、调度器
src-tauri/   命令（invoke）、事件、凭据弹窗桥接
ui/          前端
```

`core` 不依赖 IO，这样 AC-08/09/10/14/17 等大部分验收可以在纯单元测试里完成，不需要真服务器。

## 3. 逐条可行性评估

图例：✅ 直接可行　⚠️ 可行但有风险或需验证　❓ 需求需要澄清

### 3.1 范围、数据与存储

| 需求 | 评估 | 说明 |
|---|---|---|
| SCOPE-01–04 | ✅ | 配置驱动、三类执行能力，边界清晰 |
| DATA-01/02 | ✅ | UUID v7；运行快照整体序列化保存 |
| DATA-03 | ✅ | 纯校验逻辑 |
| DATA-04 原子保存 + 备份 | ✅ | Windows 上 `rename` 覆盖可用；杀毒软件偶尔锁文件，需短暂重试 |
| DATA-04 外部修改冲突 | ✅ | 保存时比对文件 hash/修订号 |
| DATA-04 单实例 | ✅ | 单实例插件 + 文件锁 |

### 3.2 服务器与认证

| 需求 | 评估 | 说明 |
|---|---|---|
| SRV-01 字段校验 | ✅ | IPv6 地址与端口分开填写，用 `std::net` 解析 + 主机名规则 |
| SRV-02 私钥文件 | ⚠️ | OpenSSH 新格式（含加密）支持良好；**老式 PEM 加密私钥、PuTTY `.ppk` 支持需验证**，不支持时要明确报错并提示转换 |
| SRV-02 SSH Agent | ⚠️ | Windows 有两种 Agent：OpenSSH 服务（命名管道）和 Pageant。russh 对两者的支持**需在阶段 0 实测**；建议 P0 只承诺 Windows OpenSSH Agent，Pageant 视验证结果 |
| SRV-02 运行时密码 / 环境变量密码 | ✅ | 注意：从资源管理器启动的 GUI 只能读到登录时的环境变量，用户新设变量后需重启应用。界面应提示这一点 |
| SRV-03 主机身份 | ✅ | 自建信任库（不改写用户的 `~/.ssh/known_hosts`），SHA-256 指纹由 russh 提供 |
| SRV-04 连接测试 | ✅ | 错误分类（DNS/拒绝/超时/认证/主机密钥/命令）可通过 IO 错误类型区分 |
| SRV-05 修改与删除 | ✅ | 纯逻辑 |

### 3.3 步骤与执行

| 需求 | 评估 | 说明 |
|---|---|---|
| STEP-01 公共字段 | ✅ | |
| STEP-02 PowerShell / cmd | ⚠️ | **编码风险**：中文 Windows 下 cmd 和外部程序输出常是 GBK（代码页 936），PowerShell 5.1 也不是 UTF-8。需要：每个 Shell 可配置输出编码（默认自动检测，失败回退 GBK），或启动时设置 `chcp 65001`/`[Console]::OutputEncoding`。建议在 SRS 里补一条 |
| STEP-02 Bash / WSL | ✅ | `wsl.exe -d <发行版> --cd <Linux 目录> -- bash -c ...`；WSL 输出本身是 UTF-8，但 `wsl.exe` 自身的错误信息是 UTF-16，需单独处理 |
| STEP-02 终止进程树 | ✅ | Job Object；WSL 内进程通过结束 `wsl.exe` 后能否全部终止需验证 |
| STEP-03 SFTP 上传 | ✅ | 递归、隐藏文件、拒绝符号链接、按当前账号创建父目录，均可实现 |
| STEP-04 单文件安全替换 | ⚠️ | SFTP v3 标准 `rename` 遇到已存在目标会失败；原子覆盖要用 OpenSSH 扩展 `posix-rename@openssh.com`。**需验证 russh-sftp 是否支持该扩展**，不支持就自己发扩展请求。服务器不支持时按 SRS 直接失败，这一点文档已经设计好了 |
| STEP-04 进度、清理临时文件 | ✅ | |
| STEP-05 SSH 远程命令 | ✅ | 每步独立 exec 通道，不分配 PTY；无 `exit-status` 即“结果未知”，与 SRS 一致 |
| STEP-06 人工确认 | ✅ | 调度器里的一个等待状态 |

### 3.4 变量与预检

| 需求 | 评估 | 说明 |
|---|---|---|
| VAR-01/02 | ✅ | 小型模板解析器：`${name}`、`${project.root}`、`${server.host}`、`${env.NAME}`、`$${` 转义、16 层递归、循环检测带引用链 |
| VAR-03 脱敏 | ⚠️ | 已知敏感值做字符串替换脱敏可行；**若敏感值很短（如 `123`）会误伤正常输出**，建议规定敏感值最短长度或接受误遮蔽 |
| RUN-01/02 预检与确认 | ✅ | 纯本地计算，不联网 |

### 3.5 调度、取消与状态

| 需求 | 评估 | 说明 |
|---|---|---|
| RUN-03 步骤优先串行 | ✅ | 任务展开是纯函数，7/10 个任务的用例可直接单测 |
| RUN-04 失败策略 | ✅ | |
| RUN-05 本地取消 | ✅ | Job Object |
| RUN-05 远程取消 | ⚠️ | 关闭通道不会杀远端进程（文档已认识到）。建议实现：远程命令用 `setsid` 包装并先回传进程组 ID，取消时另开通道执行 `kill -TERM -<pgid>`，再检查是否仍存活；能确认就记“已取消”，不能就记“结果未知”。这是**增强**，不做也满足 SRS，但做了能显著减少“结果未知” |
| RUN-06 状态规则 | ✅ | 建议用显式状态机 + 单测覆盖全部转移 |
| RUN-07 异常退出 | ✅ | 启动时扫描 SQLite 中未终结的运行，标为已中断 |

### 3.6 sudo 与凭据

| 需求 | 评估 | 说明 |
|---|---|---|
| SEC-01 SSH 与 sudo 分离 | ✅ | |
| SEC-02 免交互 | ✅ | `sudo -n -u <用户> -- sh -c '<命令>'`，未授权立即失败 |
| SEC-02 运行时密码 | ⚠️ | 用 `sudo -S -p '<随机标记>'`，密码经 stdin 写入，不进命令行参数。先用 `sudo -n true` 探测是否需要密码。风险：①部分老系统 sudoers 配了 `requiretty`，不分配 PTY 会被拒，需要明确报错；②`-S` 占用 stdin，P0 远程命令本身非交互，可接受；③密码从 WebView 经 Tauri IPC 传到 Rust，JS 侧字符串无法擦除，需关闭 IPC 日志 |
| SEC-03 凭据生命周期 | ✅ | 按（运行、服务器、登录身份、提权目标）缓存，结束即丢弃 |
| SEC-04 上传与特权边界 | ✅ | 不做 sudo 上传，正好降低复杂度 |

## 4. 文档里没有覆盖、建议补充的点

> v0.3：以下各项的结论见第 6 节。

1. **输出编码**（见 3.3）：建议新增一条需求，规定本地命令的输出解码策略。
2. **应用数据位置**：工作区、信任库、历史放在 `%APPDATA%` 还是可选路径？是否支持便携模式？
3. **安装与更新**：MSI 还是 NSIS 安装包？是否需要自动更新（Tauri updater 需要签名和发布地址）？代码签名证书没有的话，SmartScreen 会警告。
4. **SSH 算法兼容范围**：老服务器可能只支持 `ssh-rsa`（SHA-1）。是否允许？建议默认禁用、可按服务器开启。
5. **私钥格式**：是否需要支持 PuTTY `.ppk`？
6. **原 Demo**：两份文档都提到“单文件 GUI Demo”，但仓库里没有。如果还在，建议放进仓库作参考。
7. **产品名**：文档叫 Deploy Workbench，仓库叫 MyDeployMate，建议统一（影响安装包名、数据目录名）。

完成说明（2026-10-21）：全部在 `mdm-core` 中，模块为 `template`（模板语法）、`resolve`（变量解析，外部值经 `ValueSource` 注入）、`redact`（整段与流式脱敏）、`plan`（`build_plan` = PlanBuilder + 预检）、`machine`（`RunMachine` 状态机）。另外以单测覆盖了 AC-07（禁用步骤）、AC-19（人工确认）、AC-22（结果未知）、AC-27（跳过该服务器）、AC-28（服务器优先带确认）的纯逻辑部分。实现中定下的细节：

- 内建变量为 `${project.root}`、`${project.name}`、`${server.host|name|port|user}`、`${run.env}`、`${env.NAME}`；其他 `${project.x}` 等报“内建变量不存在”。
- 来自环境变量和凭据管理器的值原样使用，不再展开其中的 `${`；运行覆盖的 version 也按字面使用。引用了敏感变量的普通变量同样被遮蔽。
- version 去首尾空白后校验（RUN-02）；未填写且没有 version 变量时预检报“请填写本次发布的版本”。

## 7. 原 Demo（server_manager_demo.py）对照

Demo 是一个 Python 标准库起的本地 HTTP 服务，真正的界面是内嵌的单页 HTML + 原生 JS（约 7 万字符），所有 SSH、命令、上传、资源指标都是模拟，配置存在浏览器 localStorage。我读了它的数据模型、样例数据、样式变量和核心函数（`resolve`、`makeTasks`、`preflight`、`testServers` 等）以及事件处理，没有逐行读完每个 `render*` 函数的 HTML 模板。

### 7.1 可以直接沿用的

- **视觉风格**：CSS 变量（`--bg #f6f7f9`、`--accent #087f73`、`--red #c34a53`、`--amber #a56d18` 等）、字体（Segoe UI / 微软雅黑）、13px 基准字号、侧栏 + 编辑区 + 右侧参数面板 + 底部控制台的布局，以及 1550/1100/800px 三档响应式断点。迁移到 Vue 时整理成全局 CSS 变量文件即可。
- **图标**：Lucide 子集，换成 `lucide-vue-next`。
- **页面结构**：项目 / 服务器 / 执行记录 / 模板 / 设置五个一级页，项目内页签（流程、目标、变量、设置），和 IXD-02 基本一致。
- **任务展开顺序**：`makeTasks` 已经是“步骤优先、服务器依次展开、本地与人工确认只执行一次”，和 RUN-03 一致。
- **样例数据**：四个项目、五台服务器可改写成测试夹具和 P09 模板素材。
- **已有的交互细节**：Ctrl+S 保存、Esc 关闭、弹窗内 Tab 焦点循环、离开页面时的未保存提醒。

### 7.2 SRS 已改变、Vue 版不能照搬的

| Demo 现状 | SRS 要求 | 影响 |
|---|---|---|
| 有独立“健康检查”步骤类型 | 只有本地命令、上传、远程命令、人工确认四类（STEP-06） | 健康检查改为模板里的远程命令 |
| 服务器有跳板机字段 | 跳板机属于 P1 | P0 表单去掉 |
| 服务器有 online/offline、CPU/内存指标、拓扑图、内置终端 | P0 不做监控与终端（IXD-02），状态只表示“最近测试结果”（SRV-04） | 这些区域整体去掉 |
| 项目 `targets` 是一个扁平列表，按环境过滤 | 每个环境单独保存服务器集合（DATA-03） | 数据模型要改 |
| `continueOnError` 是布尔值 | 三值：继承流程 / 失败停止 / 失败继续（STEP-01） | |
| Shell 默认“系统默认” | 必须显式选择并预览可执行程序（STEP-02） | |
| `resolve` 不递归、不检测循环，本地命令也能用 `server.*`，预览用第一台服务器代替全部 | 递归 16 层 + 循环检测、本地上下文禁止 `server.*`、逐台预览（VAR-02/03） | 解析器在 Rust 重写 |
| 内建变量 `environment` 表示当前环境 | `env.NAME` 表示**客户端进程环境变量**（VAR-02） | 注意命名冲突：当前环境名需要另起名字，例如 `${run.env}`，建议在 SRS 中写明 |
| 服务器认证只有 `credential` 一个字段，无提权配置 | 认证方式与 sudo 提权分离（SEC-01） | 表单重做 |
| 配置存在 localStorage，`schema:1` | workspace.json 原子写 + 备份 + `schemaVersion`（DATA-04、CFG-01） | Demo 导出的 JSON 可考虑写一个一次性迁移导入 |
| 所有 HTML 由字符串拼接 + `esc()` 转义生成 | Vue 模板默认转义 | 迁移时禁止使用 `v-html` 渲染日志或用户输入 |

### 7.3 结论

Demo 适合作为**视觉和布局参考**，以及验证交互流程的样例；业务逻辑（变量解析、预检、状态）和 SRS 差异较大，不建议移植 JS 代码，而是在 Rust `core` 里按 SRS 重写，Vue 只负责展示。

## 8. 阶段 0 验证结论（2026-10-21）

### 8.1 云端 Linux 验证（`spikes/ssh-spike`，russh 0.64.1 + russh-sftp 3.0.1，对 `test-env` 运行，11/11 通过）

| 检查项 | 结果 | 对实现的影响 |
|---|---|---|
| 主机密钥回调与 SHA-256 指纹 | 与 `ssh-keygen -lf` 输出一致；`check_server_key` 返回 false 即拒绝连接 | 信任库存“算法 + 指纹”，D02 直接用该格式显示 |
| 加密 OpenSSH 私钥 | 正确口令可登录；未给口令时报 “The key is encrypted”，可据此弹出“解锁私钥” | |
| PuTTY `.ppk` v2/v3 | `ssh-key` crate 的 `ppk` feature 直接支持（含 v3 Argon2 加密）；错误口令报 “incorrect MAC” | **不用自己写解析器**，原估的 2–3 天降为约 0.5 天 |
| 密码登录 | 正常 | |
| ssh-rsa（SHA-1） | **russh 默认接受 ssh-rsa**；从 `Preferred.key` 去掉 `Rsa { hash: None }` 后连接只支持 ssh-rsa 的服务器会失败，错误信息列出双方算法；开启后主机密钥和 RSA 用户认证都成功 | 默认配置必须主动去掉 ssh-rsa，开关打开时再加回；错误信息可用于 IXD-18 的提示 |
| 退出码 | 正常获取；进程被 kill 时只收到 exit-signal、没有 exit-status | 没有 exit-status 即“结果未知”，同时记录 signal 名称 |
| sudo | NOPASSWD 下 `sudo -n` 成功；无权限时 `sudo -n` 报 “a password is required”（**与需要密码无法区分**）；`sudo -S -p <标记>` 经 stdin 输入密码成功，sudo 进程 cmdline 中无密码；错误密码可从提示标记计数；requiretty 报 “you must have a tty” | 无权限与需要密码都按“需要密码”处理，输入后仍失败再报未授权；按提示标记判断重试次数 |
| 远程取消 | signal 请求和关闭通道后进程都仍在运行；`setsid` 记录进程组后从另一通道 `kill -TERM -- -<pgid>` 可确认全部结束 | 远程命令统一用 `setsid` 包装并回传进程组 ID；取消 = 进程组 kill + 存活检查，检查不到才记“结果未知” |
| SFTP 原子覆盖 | 服务器通告 `posix-rename@openssh.com`；标准 rename 覆盖已存在文件失败；通过 `RawSftpSession::extended` 发送 posix-rename 成功；写无权限目录返回 Permission denied | russh-sftp 没有封装 posix-rename，需自己发扩展请求（已验证，约 20 行代码）；连接时检查是否通告该扩展 |
