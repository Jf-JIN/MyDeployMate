## 1 目的、范围与术语

### SCOPE-01 产品目标

将固定服务器和特定语言的部署工具重写为配置驱动的桌面部署工作台。新增服务器、项目、构建命令、上传路径和远程操作时，不应要求修改程序源码。语言无关表示不判断或强制绑定 Python、Rust、TypeScript、JavaScript 等语言；不表示自动安装工具链、自动生成正确构建命令或保证任意命令跨平台运行。

### SCOPE-02 执行边界

基础执行能力仅为本地命令、SFTP 上传和 SSH 远程命令；人工确认属于流程控制。Git 拉取、远程编译、Docker 操作、重启和健康检查均为普通命令配置或模板，不建立“Git 执行器”“Rust 执行器”或“CI/CD 执行器”。本应用不是完整持续集成平台，P0 不包含提交触发器或常驻 Runner。

### SCOPE-03 版本范围

P0：Windows 客户端、Linux SSH 目标、单机单操作者；服务器与环境配置、项目与流程、变量、三类执行能力、人工确认、预览、串行执行（两种顺序）、取消、记录、JSON 导入导出、SSH 主机身份验证和 sudo。

**【v0.2】** P0 GUI 技术栈为 Tauri 2 + Rust 后端 + Vue 3 / TypeScript 前端。P0 不包含模拟模式；原 Demo 作为独立原型保留在仓库 `demo/` 目录。

建议 P1：跳板机、完整交互终端、并行任务、模板管理、可配置 Bash（Git Bash 等）。建议 P2：定时与事件触发、多人审批、滚动发布、自动重试及回滚。P1/P2 是候选方向，不是承诺。

### SCOPE-04 术语

“环境”是 development/staging/production 等逻辑分组；“项目”是被部署对象及其配置；“流程”是有序步骤集合；“步骤”是可复用配置；“任务”是步骤在一次运行中的实例；“运行”是配置快照与所有任务的集合；“模板”只生成可编辑配置，不能增加隐含执行行为。

## 2 对象与一致性规则

### DATA-01 基本对象

Workspace 包含环境、服务器、项目、全局变量及偏好；Project 包含根目录、项目变量、环境覆盖、环境目标绑定及多个流程；Pipeline 包含有序 Step；Run 包含配置快照、Task、日志、操作者与起止时间；CredentialRef 只引用认证来源。实现可采用文件或数据库，但必须保持这些逻辑边界。

### DATA-02 标识与引用

所有环境、服务器、项目、流程、步骤、运行和任务具有不可变唯一 ID。重命名不改变引用。复制项目或流程必须为其包含对象生成新 ID。运行快照保存当时名称与必要配置；当前对象删除或改名不得篡改历史。引用不存在的对象时配置不得生效。

### DATA-03 环境与目标

环境字段：名称必填，去首尾空白后 1–32 字符、工作区内唯一；保护环境开关默认关闭。预置 development、staging、production，其中 production 保护开关开启。服务器归属一个环境；项目分别保存各环境的显式服务器 ID 集合。增加服务器或改变标签不自动绑定项目；仅能绑定当前项目环境下的服务器。环境有服务器、项目引用或活跃运行时禁止直接删除，并列出引用。

### DATA-04 保存与并发

配置采用显式保存。离开脏表单时提供保存、放弃、取消；保存失败保留编辑内容。落盘必须原子替换并保留上一份成功配置备份。外部修改造成版本冲突时不得静默覆盖，提示重新加载或另存导出。P0 同一工作区只允许一个活跃运行；第二实例不得并发写入该工作区。

## 3 服务器与认证

### SRV-01 服务器字段

名称：必填、去空白后 1–64 字符、工作区内唯一。地址：必填，支持 DNS、IPv4、IPv6，不含协议、路径或端口，IPv6 端口单独填写。端口：默认 22、整数 1–65535。登录用户：默认 deploy、必填且不含空白。环境：必选。标签：可空多值，不影响权限或目标选择。备注：可空，最多 2000 字符。建议连接超时 10 秒，可配置为 1–120 秒。

**【v0.2】** 允许旧算法：开关，默认关闭。开启后该服务器允许使用 `ssh-rsa`（SHA-1 签名）主机密钥与用户认证算法；关闭时遇到只支持该算法的服务器，连接失败并提示可在此开启。修改该开关与修改认证来源同等对待，清除旧测试结果。

### SRV-02 认证方式

支持私钥文件、SSH Agent、运行时密码、密码环境变量引用。私钥方式保存本地路径，不保存私钥正文；加密私钥口令仅运行时输入（或按 SEC-03 可选保存）。Agent 不可用时明确报错，不自动切到其他账号。密码环境变量方式保存变量名称并从客户端进程环境读取；缺失或空值在连接前报错。不得将 SSH 登录密码、私钥口令、sudo 密码写入普通配置。

**【v0.2】** 私钥文件支持 OpenSSH 格式（含加密）和 PuTTY `.ppk` v2/v3（含加密）。无法识别的格式必须明确报出“不支持的私钥格式”及文件路径，不得笼统报认证失败。密码环境变量方式需在界面提示：环境变量在应用启动时读取，修改后需重启应用。

### SRV-03 主机身份

首次遇到主机公钥时展示地址、端口、密钥类型和 SHA-256 指纹，等待用户核对后信任或取消；不能自动信任。已知密钥变化时中止连接，显示旧、新指纹，通过独立的显式信任更新流程处理。连接测试和实际运行使用同一信任策略。首次信任只确认该主机身份，不代表信任其输出的指令或文本。信任库由本应用独立保存，不读写用户的 `~/.ssh/known_hosts`。

### SRV-04 连接测试

保存服务器不触发连接；初始状态为“未测试”。单独测试执行 SSH 认证并执行无副作用探测命令，记录时间、耗时与结果，不测试 sudo 权限。区分解析失败、拒绝连接、超时、认证失败、主机密钥问题和远程命令失败；失败不得伪装为“离线”。批量测试逐个显示结果，不因一台失败隐藏其他结果；取消批测只停止未开始测试。

### SRV-05 修改与删除

修改地址、端口、账号、认证来源、允许旧算法后清除旧测试有效标记；修改名称和标签不影响测试结果。改环境时必须显示并确认移除原环境项目绑定，不能静默迁移。删除前列出项目引用，经确认后移除绑定，保留历史快照；活跃运行引用的服务器禁止删除或修改连接字段。测试成功仅是当时结果，执行仍需重新连接。

## 4 项目、流程与模板

### PRJ-01 项目字段

项目名称必填、去空白后 1–64 字符、工作区内唯一；说明最多 2000 字符；根目录为可选本地绝对路径，使用本地相对路径的步骤必须配置。默认环境必选。不存在“编译语言”必填字段。项目包含至少一个流程；流程名称必填、项目内唯一。执行中允许编辑配置，但仅影响后续运行；删除活跃运行引用的项目或流程禁止。

### PRJ-02 流程编辑

步骤支持新增、复制、启用禁用、上移下移和删除。复制产生新 ID；禁用步骤不校验执行参数、不生成任务。上移下移保留步骤身份与选中状态。流程空或没有适用的启用步骤时禁止运行。用户必须能查看实际顺序，不通过名称排序决定执行顺序。

**【v0.2】** 流程级设置包含：失败策略（默认失败停止）和执行顺序（步骤优先 / 服务器优先，默认步骤优先），语义见 RUN-03、RUN-04。

### PRJ-03 模板

P0 提供空白流程、本地构建后上传发布、远端获取代码后部署三类示例模板。语言命令可作为示例文案或配置值，不构成引擎分支。模板导入后成为独立可编辑步骤；后续模板变化不得修改已有项目。远端获取私有仓库时，目标服务器到仓库的认证独立于客户端 SSH 登录，软件不得承诺复用成功。

## 5 步骤规格

### STEP-01 公共字段

每个步骤包含 ID、名称、类型、启用状态、超时和失败策略。名称必填 1–64 字符。命令和上传超时默认 300 秒，范围 1–86400 秒；人工确认不设执行超时。用户取消不是普通失败，即使失败继续也应停止调度。

**【v0.2】** 失败策略为：继承流程、失败停止、失败继续、跳过该服务器。流程默认失败停止。“跳过该服务器”只在流程执行顺序为服务器优先时可选；步骤优先流程中选择它时预检报错。本地步骤和人工确认不可选“跳过该服务器”。

### STEP-02 本地命令

字段为命令文本、工作目录、Shell、输出编码。命令必填；目录默认项目根目录且在任务开始前校验存在。Shell 必须显式选择并预览解析后的可执行程序。WSL 必填发行版且使用 Linux 内部目录；不得自动猜测 Windows/WSL 路径。一次运行仅执行一次，不按服务器复制。捕获标准输出、标准错误、退出码和耗时。前一步的 cd、Shell 变量及环境修改不传递到下一步。

**【v0.2】** P0 支持的 Shell：PowerShell（5.1 及 7）、cmd、WSL；可配置 Bash 移至 P1。

**【v0.2】** 输出编码：可选“自动”（默认）、UTF-8、GBK。自动模式下按字节流逐段尝试 UTF-8 解码，失败时回退到系统 ANSI 代码页（中文 Windows 为 936/GBK）。程序不得为修正编码而改写用户命令或运行环境（例如自动插入 `chcp 65001`）。WSL 步骤默认按 UTF-8 解码；`wsl.exe` 自身输出的错误信息按 UTF-16 处理。无法解码的字节以替换字符显示，原始字节不丢弃到日志之外。

### STEP-03 SFTP 上传

字段为本地源路径、远端目标绝对路径、源类型（文件或目录）、冲突策略（报错或覆盖，默认报错）。文件目标必须是完整文件路径；目录目标表示上传其内容，不额外套源目录名。递归包含隐藏文件，不镜像删除远端额外文件；P0 拒绝符号链接及特殊文件并明确报错。每个目标服务器生成一个任务。缺失的父目录按当前 SSH 账号权限创建；权限不足失败，不自动 sudo。

### STEP-04 上传一致性

源文件存在性在上传任务开始时检查，允许前序构建生成产物。预检检查路径语法，不因尚未生成产物阻止构建。上传以临时文件加重命名提交单个文件；覆盖目标时若服务器不支持所需安全替换操作（`posix-rename@openssh.com`）则失败，不先删除原文件。**【v0.2】** 同一运行中，上传步骤的第一个目标开始传输前记录每个源文件的 SHA-256；后续目标开始前重新核对，文件增删或内容变化时该任务失败并列出变化的文件，按失败策略处理，不复制本地快照。目录上传不保证整目录事务；失败需列出已提交、失败及未处理文件，清理本次临时文件并记录清理结果。进度按已传字节与文件数显示。

### STEP-05 SSH 远程命令

字段为命令文本、工作目录、提权策略。命令必填；目录为空时使用登录账号默认目录，非空必须是远端绝对路径。每个目标服务器生成一个任务；每个命令使用独立执行上下文，不跨步骤继承 cd 或 export。默认非交互执行，P0 不支持全屏程序及任意交互问答；只有产品管理的认证和 sudo 输入允许交互。记录退出码；退出码 0 成功、非 0 失败，无法确认退出码时结果未知。

**【v0.2】** 命令有两种写法：脚本（默认，命令文本由远端 `sh -c` 解释）和程序及参数（可执行文件绝对路径加参数列表，逐个参数转义，不经 Shell 运算）。两种写法都可使用任意提权策略；脚本写法提权时以 `sudo … sh -c` 执行，需要服务器授权 Shell，确认界面须提示这一点；程序写法提权时直接以 sudo 调用该程序，可匹配 sudoers 中精确到命令的授权。

### STEP-06 检查与人工确认

健康检查使用普通本地或 SSH 命令，例如 curl，其成功判定仍为退出码 0；不增加健康检查专用执行器。人工确认是流程控制节点，包含必填提示文本；按流程执行一次，显示版本、环境、目标和此前任务结果，确认后继续、取消后停止。确认仅证明当前操作者操作，不构成多人审批或安全授权。

## 6 变量与参数解析

### VAR-01 命名与作用域

用户变量名由 ASCII 字母或下划线开头，后接字母、数字或下划线；同一作用域唯一，值为字符串。优先级从低到高为全局、项目、环境覆盖、本次运行覆盖。P0 运行覆盖仅开放 version，其他值需在配置中编辑。内建命名空间 project、server、run、env 保留，不能被用户覆盖。显式空字符串是覆盖值，删除覆盖项才恢复继承。

### VAR-02 语法与解析

采用 `${name}` 引用用户变量；`${project.root}` 为项目根目录；`${server.host}` 为当前任务目标地址；`${env.NAME}` 引用客户端进程环境变量。用户值可递归引用，最多 16 层，循环或超限必须报出引用链。用双美元前缀 `$${` 转义模板表达式以保留给 Shell。局部任务不允许引用 server 变量。未定义变量阻止开始并定位到具体步骤字段。

**【v0.2】** 当前运行的环境名称使用 `${run.env}`（注意 `env.*` 表示进程环境变量，二者不可混用）；版本使用 `${version}`。

### VAR-03 预览和敏感值

实际执行值必须与最后确认的解析快照一致。预览按服务器显示差异，不使用第一台值冒充所有目标。敏感变量默认遮蔽，命令快照、日志、历史和导出中的相关值必须脱敏。**【v0.2】** 敏感变量的值不写入工作区配置，而保存在 Windows 凭据管理器，配置中只保存引用；也可改为引用客户端环境变量。导入到缺少该值的电脑时，变量标为“需填写”，使用它的运行在预检中被阻止。模板插值是文本替换，不承诺自动适配所有 Shell 的转义；普通变量来源视为受信配置，外部不可信输入不得直接拼接为可执行命令。密码及凭据禁止通过此通道拼入命令。

## 7 预检、调度与状态

### RUN-01 开始前预检

执行前必须完成：保存脏配置或取消、校验被选启用步骤、变量解析、目标引用、路径语法、Shell 配置、认证引用、版本值与失败策略和执行顺序的组合合法性。包含远程或上传步骤但没有目标时禁止开始。本次目标只能是当前环境已绑定服务器的子集；临时取消勾选不修改默认绑定。预览不连接 SSH、不执行命令、不创建远端目录。已知需要凭据的任务在真正执行前请求，无法离线证明的权限不伪报通过。

### RUN-02 执行确认

确认界面展示项目、环境、流程、version、执行顺序、范围、目标、展开后的有序任务和提权操作。version 去首尾空白后 1–128 字符且禁止换行、NUL；它不是自动可信的 Shell 参数。保护环境必须键入当前环境名称确认，修改目标或版本后清除确认。点击开始时重新检查配置版本并冻结快照；重复点击只创建一个运行。

### RUN-03 范围和顺序

**步骤优先（默认）**：按步骤优先、服务器次序固定的顺序串行执行；本地及人工确认各一次，上传和远端命令按目标逐一展开。两台服务器的构建、上传、重启、检查依次为：构建，上传 A，上传 B，重启 A，重启 B，检查 A，检查 B，共 7 个任务；三台时为 10 个。

**【v0.2】服务器优先**：流程按本地步骤和人工确认切分为若干“段”。每段内的远程类步骤（上传、远程命令）按服务器依次执行完该服务器的全部段内步骤，再进行下一台；本地步骤和人工确认在其位置执行一次，且只在前一段所有服务器完成后开始。两台服务器的构建、上传、重启、检查依次为：构建，上传 A，重启 A，检查 A，上传 B，重启 B，检查 B，共 7 个任务。若流程为“构建、上传、人工确认、重启”，则为：构建，上传 A，上传 B，确认，重启 A，重启 B。

两种顺序都不是并行执行，也不是带健康门槛的自动滚动发布。“仅本地命令”只保留本地步骤，跳过上传、远程、人工确认和 SSH 凭据请求。

### RUN-04 失败策略

失败停止：当前任务记失败，所有后续未调度任务记跳过并注明上游原因。失败继续：记录当前失败后继续后续任务，包括下一步骤中该服务器的任务；软件不推断依赖，因此该策略必须明确告知风险。

**【v0.2】** 跳过该服务器（仅服务器优先）：当前任务记失败，该服务器在本段及之后各段中的剩余任务全部记跳过并注明原因，其他服务器继续执行。所有服务器均被跳过时，后续本地步骤和人工确认也记跳过。

任意任务失败后，正常结束的运行仍为失败。P0 不自动重试、不自动回滚。

### RUN-05 取消与超时

取消立即停止新任务调度，并尝试终止当前本地进程树或远程命令、关闭传输。超时属于失败并应用失败策略；但远端退出结果不确定时立即停止整个运行，不因“失败继续”或“跳过该服务器”而接着发布。关闭 SSH 通道不能视为命令已停止，无法确认时显示结果未知并提供人工核验提示。未开始任务均记跳过；任务取消不删除已上传文件或撤销已生效命令。

### RUN-06 状态规则

任务状态：排队、运行中、等待确认、等待凭据、成功、失败、已取消、已跳过、结果未知。运行状态：排队、运行中、等待确认、等待凭据、取消中，以及成功、失败、已取消、已中断终态。所有适用任务成功才可成功；有未知任务或异常退出未能核验时运行记已中断；否则有失败为失败；否则用户取消为已取消。保留取消原因及所有子任务结果，不用汇总状态覆盖失败事实。

### RUN-07 异常退出与再次执行

运行记录在任务状态变化时持久化。应用重启发现未结束记录时记已中断，不自动续跑；显示可能仍在执行的远程任务。再次执行基于历史对应的项目和流程进入当前配置预览，并标出配置变化；不默默使用第一个流程，不直接重放旧命令。原流程已删除时禁用再次执行并说明原因。

## 8 sudo 与凭据安全

### SEC-01 SSH 和 sudo 分离

SSH 认证、加密私钥口令和 sudo 身份验证是三个独立问题。服务器默认提权策略为不提权；远程步骤可选择继承服务器、不提权、sudo 免交互、sudo 运行时密码。默认目标用户 root，允许显式配置其他用户并展示。账号密码验证主体由服务器策略决定，界面不得承诺一定是 root 密码或私钥口令。

### SEC-02 免密与密码输入

sudo 免交互采用非交互模式，服务器未授权时快速失败，不弹密码框或自动切换 root。NOPASSWD 是管理员配置的服务器授权，不是 GUI 保存密码。运行时密码模式使用独立受控输入渠道（标准输入），禁止进入命令行参数、历史、普通日志或配置。先执行无凭据暴露的授权检查，需要时再提示输入；错误最多允许 3 次重试，取消视为整次运行取消。服务器要求 TTY（`requiretty`）时明确报错，不自动分配终端。

### SEC-03 凭据生命周期

默认情况下，密码和私钥口令仅在当前操作期间的内存中使用；sudo 缓存按运行、服务器、登录身份及提权目标隔离。结束、取消和退出时释放引用，尽力清理缓冲区，不宣称托管运行时可以保证物理内存擦除。服务器自身 sudo 缓存由服务器策略控制。命令输出仍可能自行产生未知秘密，产品应提示脱敏并非内容泄漏的绝对保证。

**【v0.2】可选保存**：凭据输入框提供“记住此凭据”选项，默认不勾选。勾选后凭据保存到 Windows 凭据管理器（按服务器 ID、登录用户、用途——SSH 密码 / 私钥口令 / sudo 密码及目标用户——区分条目），不写入工作区配置、导出文件、日志或历史。已保存的凭据在配置中心列出（只显示用途、服务器和用户，不显示内容），可逐条或全部清除。已保存凭据验证失败时视为一次失败尝试，并提示用户重新输入；重新输入成功后才覆盖保存值。删除服务器时一并删除其已保存凭据。

### SEC-04 上传与特权边界

SFTP 不受 sudo 步骤影响。需要写受保护目录时，用户配置上传到当前账号可写的暂存目录，再用单独的授权远程命令安装或移动文件；每个命令分别预览。软件不自动扩大 sudoers 权限、不提供默认全命令免密规则、不隐式上传私钥到服务器。

## 9 日志、历史与配置交换

### OBS-01 运行日志

每条日志包含时间、运行 ID、任务 ID、步骤名称、服务器或本地标识、来源和文本。保留 stdout/stderr 的各自顺序，不声称能精确还原两条流的全局发生顺序。可筛选任务、服务器和错误；筛选不得删除原始内容。用户上滚暂停自动跟随，点击跟随恢复；无换行输出也应持续显示。终端控制字符不得执行脚本或控制应用界面；日志一律按纯文本渲染。

### OBS-02 历史与导出

历史展示运行时间、项目、流程、环境、版本、目标、耗时与汇总状态；详情显示配置快照、展开任务、退出码、传输结果、日志、确认与取消事件。历史命令使用脱敏快照，密钥路径等本机信息导出时允许排除。日志导出保留时间和上下文并提示检查敏感信息。删除记录需确认，活跃记录不可删除。

### CFG-01 导入导出

P0 支持带 schemaVersion 的 UTF-8 JSON 工作区配置。导出不包含私钥正文、密码、信任库、已保存凭据、**【v0.2】** 敏感变量的值或运行日志；保存的环境变量名及凭据引用可保留，必须说明其不是实际凭据。导入 P0 采用全量替换，不提供含糊合并：预览新增、修改、删除及引用变化，确认前不修改当前工作区；成功前备份旧配置。

### CFG-02 导入验证

检查 JSON 格式、版本、必填字段、类型、唯一 ID、环境及目标引用、步骤枚举、失败策略与执行顺序组合、变量语法。未知主版本拒绝，不能忽略未知执行类型。任一错误整批拒绝，保留现有数据并定位对象字段；本机绝对路径不存在标为需修复，不替用户执行命令。活跃运行禁止导入替换。导入永不直接执行。

## 10 非功能需求

### NFR-01 响应与容量

验收基线：Windows 11、4 核 CPU、16 GB 内存、SSD；100 台服务器、50 个项目、每流程 50 个步骤、1000 条历史摘要。常规导航和选择反馈应在 200 ms 内出现，冷启动到可操作小于 3 秒，运行时日志到达后 1 秒内可见。连续输出 10000 行应支持浏览和取消，不在 UI 主线程同步等待网络。以上须在指定测试环境实测，不是现有性能声明。

### NFR-02 可用性与存储

桌面最小目标视口为 1280×720，显示缩放 125% 下关键操作不被遮挡。键盘可到达全部主要操作，焦点可见；状态同时使用文字与符号，不仅用颜色。每运行日志上限 50 MiB、历史默认保留 90 天；达到日志上限后停止持久化新增正文但继续排空输出、保留状态与截断标记。磁盘不足不得假报保存成功，默认停止安排新发布任务并保留内存结果。

**【v0.2】** 应用数据（工作区配置及备份、主机信任库、运行历史、日志）保存在 `%APPDATA%\MyDeployMate`。配置中心提供“打开数据目录”。P0 不提供便携模式。

### NFR-03 可维护与兼容

配置及历史具有版本标记；升级前备份且失败后能恢复旧配置。错误必须含对象、阶段和可采取的下一步，不直接暴露凭据。业务配置变更无需重编译程序；新增基础执行类型才允许要求修改引擎与界面。程序支持不依赖外部网络的配置编辑和预览，实际命令的网络需求由用户自行配置。

### NFR-04 安装与更新 【v0.2 新增】

发布形式为 NSIS 安装包，经 GitHub Actions 构建并发布到仓库的 GitHub Releases。应用启动时检查 Releases 上的新版本（可在配置中心关闭），有新版本时提示用户，由用户确认后下载并安装；有活跃运行时不得安装更新。更新包必须经过更新签名校验，签名私钥不进入仓库。P0 不做代码签名证书，接受 Windows SmartScreen 的未知发布者提示。更新前按 NFR-03 备份配置。检查更新失败不影响正常使用，也不得反复弹窗。
