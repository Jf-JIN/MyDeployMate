# 发布流程

对应 SRS NFR-04、架构 ADR-11、计划 8.4 / 8.4b。

## 一次性准备

1. 在 `MyDeployMate-Tauri` 目录生成更新签名密钥（只做一次）：

   ```powershell
   npx tauri signer generate -w $env:USERPROFILE\.tauri\mydeploymate.key
   ```

   私钥文件和密码要备份好：丢了以后，已安装的版本就再也收不到更新。
2. 仓库 Settings › Secrets and variables › Actions 新建：
   - `TAURI_SIGNING_PRIVATE_KEY`：私钥文件 `mydeploymate.key` 的内容
   - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`：生成时设的密码
3. 公钥 `mydeploymate.key.pub` 的内容填进 `src-tauri/tauri.conf.json` 的 `plugins.updater.pubkey`。公钥可以公开。

## 每次发布

1. 把 `Cargo.toml`（workspace）和 `package.json` 的版本改成新版本，例如 `0.2.0`，合并到 main。
2. 在 main 上打带注释的标签，注释就是更新说明（会显示在更新弹窗里）：

   ```bash
   git tag -a v0.2.0 -m "新增英文界面
   修复变量页横向滚动"
   git push origin v0.2.0
   ```

3. `Release` 工作流在 Windows 上构建 NSIS 安装包，用私钥签名，建一个**草稿** Release，附带
   `MyDeployMate_0.2.0_x64-setup.exe`、它的 `.sig` 和 `latest.json`。
4. 下载安装包试装，没问题后在 GitHub 上把草稿发布。发布之后，已安装的旧版本启动时才会检查到它。

想先试构建和签名、不建 Release：在 Actions 页手动运行 `Release`，安装包会作为工作流产物上传。

## 应用里的行为

- 启动时（配置中心 › 更新 › “启动时检查更新”开启时）后台读取
  `releases/latest/download/latest.json`，失败只在配置中心显示，不弹窗。
- 有新版本时图标栏底部出现带标记的更新图标，点开显示版本和更新说明。
- 有运行进行中时不能安装。下载后先校验签名和签名里记录的版本（`requireSignedVersion`），
  校验失败显示“更新包校验失败，已停止安装”；通过后把配置备份到数据目录的 `backups`，再启动安装程序，
  应用关闭，安装完成后重新打开。
- 不做代码签名证书：首次安装时 Windows SmartScreen 会提示“未知发布者”，选“仍要运行”。
